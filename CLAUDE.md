NuGet package (`QueryBuilder.Editor`) with a React/TS/Tailwind/shadcn frontend built and embedded
into the assembly. Sibling product to `TemplateBuilder.Editor` — mirrors its architecture and
integration ergonomics (single-call registration, embedded SPA, DBA-friendly migrations).

`Domain`/`Application`/`Infrastructure` are never published standalone — `QueryBuilder.Editor`
bundles their compiled DLLs into its own package (`BundleInternalAssemblies` MSBuild target) so a
consumer only ever installs one package. `IsPackable=false` + `PrivateAssets="all"` on those

**Mediator**: MediatR now requires a paid license, so this project uses a small in-house
`IRequest`/`IRequestHandler`/`ISender` in `Application/Common/Mediator.cs`. Don't reintroduce
MediatR.

the package's JSON contract independent of whatever (if anything) the host app configured in its

## Known sharp edges (already hit once — don't reintroduce)

- **`AppId` database defaults live outside the EF model** (`DF_<Table>_AppId`, added by raw SQL in `AddApps`). A future
  migration that `AlterColumn`s an `AppId` makes EF drop that default without re-adding it — re-add it by hand in the same
  migration. Every app-owned entity must implement `IAppOwned` (`AppModelTests` reads the EF model and fails otherwise), and
  anything cached by an id must be gated by a filtered lookup first (the catalog and data-scope caches were cross-app holes).

- **PostgreSQL reads are text-mode on purpose.** `PostgresQueryExecutionService` sets
  `AllResultTypesAreUnknown = true` and parses each cell by its reported type in `PostgresValueParser`, because
  Npgsql's typed reads throw on values .NET can't hold (`infinity`, BC and year>9999 dates, huge `numeric`). A
  `numeric` becomes `decimal` only if formatting it back gives the identical string; otherwise it stays text.
  Don't switch to typed reads.
- **PostgreSQL session settings only apply when pinned to one transaction.** Read-only, `statement_timeout`,
  `DateStyle`, `TimeZone`, `IntervalStyle` and `extra_float_digits` are set with `LOCAL` inside the execution's
  transaction, which is rolled back. Never set them session-wide: pooled connections (and PgBouncer) would leak
  them to other callers.
- **`::text` and collations on PostgreSQL.** Text and Unknown columns are cast `::text` in filters and scope
  predicates; contains/starts/ends use `col::text COLLATE "default" ILIKE @p ESCAPE ''` (`ILIKE` errors on a
  nondeterministic collation even after `::text`; `ESCAPE ''` stops `\` acting as an escape). But `IN` with
  `::text` still follows a nondeterministic column's collation (`'acme'` matched `ACME`), so such a column can't
  be a scope column. Whole numbers bind as `bigint`, not `decimal`, or Postgres casts the column and skips its
  index.
- **Clashing `schema.name` objects (PostgreSQL) are unavailable, not hidden.** Names equal ignoring case
  (`public.Orders` / `public.orders`, or `a.b`+`c` vs `a`+`b.c`) go to `DataSourceCatalog.UnavailableObjects`
  (no columns, never in `Schemas`), because `DataScopeRules`' unique index is case-insensitive on typical
  metadata collations. Scoped users get none of them. Saving data scope or catalog policy must carry existing
  decisions on unavailable objects forward. Identifier matching goes through the provider's comparer
  (`IdentifierMatching`: Ordinal for PostgreSQL, OrdinalIgnoreCase for SQL Server), never a hardcoded
  `OrdinalIgnoreCase`.

- **Zustand selectors must never return a newly-constructed array/object** (e.g.
  `useStore(s => s.items.filter(...))`). Breaks `useSyncExternalStore`'s snapshot-stability
  contract → infinite render loop (React error #185). Select the stable underlying state, then
  `.filter()`/`.map()` as a plain expression in the render body instead.
- **Radix `ScrollArea` wraps children in an internal `display:table; min-width:100%` div** (for a
  horizontal scrollbar this app never renders) — it shrink-to-fits content instead of respecting
  the viewport width, silently clipping anything that should have truncated. Already fixed in
  `client/src/components/ui/scroll-area.tsx` via `[&>div]:!block` on the Viewport — don't remove
  that.
- **Tailwind `truncate` on a flex child does nothing without `min-w-0` on that same element** — a
  flex item's default `min-width: auto` blocks it from shrinking below content width even with
  `overflow:hidden` set. Pattern used throughout: `min-w-0 flex-1 truncate` on the text span,
  `shrink-0` on fixed-width siblings.
- **Adding a new EF entity via an already-tracked parent's navigation collection**
  (`parent.Children.Add(newChild)`) can leave the change tracker inferring `Modified` instead of
  `Added` when the child has a non-default client-generated key (our `Guid`s are all
  `= Guid.NewGuid()` property initializers) — produces an `UPDATE` matching zero rows
  (`DbUpdateConcurrencyException`). Always add new child entities directly via the `DbSet`
  (`db.QueryShares.AddAsync(share)`), not through the parent's collection. See
  `SavedQueryRepository.AddShareAsync`/`RemoveShare` for the pattern to copy for any future
  child-entity type.
- **`dotnet pack` on a multi-project-bundled package needs a `dotnet clean` first** — incremental
  builds don't always regenerate the embedded-files manifest after `wwwroot` changes.
- **Multi-targeting:** EF Core versions are conditional on `$(TargetFramework)` in `Infrastructure` and `Editor`
  (keep them in step), and `Microsoft.Extensions.*` must be at least what EF 10 requires, or restore fails on a
  downgrade. The internal DLLs are bundled through `TargetsForTfmSpecificBuildOutput`, since the outer pack has no
  `$(TargetFramework)`. After changing target frameworks use `dotnet restore --force`: a stale restore left the
  sample app on EF 9 under `net10.0`, visible only as an MSB3277 warning.
- **TanStack Query v5 throws if a `queryFn` resolves to `undefined`** (`"<queryHash> data is
  undefined"`), which puts the query into an error state — `isSuccess` never becomes `true`, with no
  console error pointing at the cause. Bit us in `useAdminAccess` (`client/src/hooks/useAdmin.ts`),
  whose probe endpoint returns `void`/204: `queryFn: someApiCall` where `someApiCall` returns
  `Promise<void>` silently breaks any UI gated on that query's success. Fix: wrap it to resolve a
  real value, e.g. `queryFn: async () => { await someApiCall(); return true }`.
- **A client-side react-query cache with a `staleTime` can silently undo a server-side cache
  eviction.** When a mutation's `onSuccess` only invalidates its own detail query, a *different*
  query key reading related data (e.g. the business-facing catalog after an admin changes a data
  source's policy) keeps serving stale data for up to `staleTime` on in-SPA navigation — a full page
  reload masks this because it wipes the whole client cache, so a Playwright check that always
  reloads won't catch it. When a mutation changes something another query key depends on, invalidate
  that key too in the same `onSuccess` (see `useUpdateCatalogPolicy` in `client/src/hooks/useAdmin.ts`
  for the pattern: invalidates `['data-source-catalog', id]` and `['data-sources']` alongside its own
  key).
- **Run/export/preview trust the `QueryDefinition` the browser sends** — the server never re-loads a
  saved definition. So anything security-relevant (row-level data scope) must be enforced
  server-side at SQL-build time, never in the UI or the saved query. Every business-SQL path goes
  `ValidateAsync` → `IDataScopeGuard.AuthorizeAsync` → `Build(definition, scope)`; `Build`'s scope
  parameter is required on purpose so a new path can't skip it. Runtime parameter names are the
  one piece of browser text emitted raw into SQL (`@name`) — they're validated by
  `QueryParameterNames` (letters/digits/underscore, `__` prefix reserved for `@__scope0`...); an
  unvalidated name was a real injection hole until 1.0.12.
- **A C# `params object[]` + generic `IEnumerable<T>` overload pair binds a single `string` to the
  generic one** (string is `IEnumerable<char>`) — `DataScope.And("key", "14")` split into `"1"`,`"4"`.
  `DataScope` now has only the `params` overload and flattens collections (excluding strings) itself.
- **Requests made with axios `responseType: 'blob'` (export) receive their error body as a Blob
  too**, so `error.response.data.title` is undefined and every failure surfaced as a generic "Export
  failed." — the interceptor in `client/src/lib/api-client.ts` now parses JSON Blobs into
  `ApiError`. Keep that if adding any other binary-download endpoint.
- **Bodies are read with `ReadFromJsonAsync`, not minimal-API binding**, so a malformed or
  wrongly-typed body throws `JsonException` inside the handler — `GlobalExceptionHandler` maps that
  (and `BadHttpRequestException`) to 400. Before 1.0.13 both were unmapped 500s.

- **Radix `Select` inside a `<form>` can call `onValueChange('')`** while its items aren't mounted,
  silently wiping a controlled value (lost `p_status` from the URL and saved an empty default). Ignore
  `''` in handlers (see `features/parameters/controls/ListControls.tsx`).
- **react-grid-layout only exempts its own `.react-resizable-handle` from dragging.** A custom
  `handleComponent` class must be added to `dragConfig.cancel`, or a corner drag moves the tile instead
  of resizing it; the library also renders handles when resizing is disabled (hide them via CSS).
- **Playwright's default browser profile here is zoomed (~0.8–0.9 device scale)**; for screenshots use a
  fresh `browser.newContext({ viewport })` and judge by DOM measurements, not pixel sizes.
- **A stale browser-cached `index.html` hides a new bundle** (fixed with no-cache headers, but browsers
  that cached it earlier need Ctrl+F5). If a screenshot shows an old UI, compare `index-*.js` in the page
  with `wwwroot/index.html` before suspecting the build.
- **`localhost` and `https://localhost:7044` hide bugs that only appear on plain http.** Browsers leave
  `crypto.randomUUID`, `crypto.subtle` and `navigator.clipboard` undefined outside a secure context, and the
  hosted site is http: Add chart/text/section threw right after closing the dialog, so nothing was added.
  `client/tests/insecure-context.test.ts` rejects those APIs in `client/src`, comments included. To test http
  without exposing the app, route a fake origin to it in Playwright (`context.route('http://qb.test/**', …)`
  fulfilled from `route.fetch({ url })` at localhost:5080); `isSecureContext` is then really false.
- **Git Bash mangles Windows paths passed to `sqlcmd -i`**; run `sqlcmd` from PowerShell with backslash
  paths. Verify DBA scripts by applying `migrations script --idempotent` to a throwaway LocalDB database
  with `sqlcmd -I -b`, **twice**, then drop it.
- **The idempotent script compiles every batch, even for migrations it skips.** A `migrationBuilder.Sql`
  that names a column a later step drops fails on an upgraded database ("Invalid column name"), stopping a
  DBA upgrade before the newer migrations. Wrap such SQL in `EXEC(N'…')`, as
  `AddCatalogScopeAndAllowedObjects` now does (1.0.13's script had this bug). Auto-migration never hit it.

- **A blank password on edit or test keeps the stored one only if host, port and username are unchanged and
  `SslMode` isn't lowered (Disable < Require < VerifyFull).** Otherwise `400 Re-enter the password when changing the
  host, port, username or lowering encryption.` (`ManagedConnections.Resolve`); a missing `SslMode` keeps the stored
  one. A managed row whose blob can't be read refuses a blank password outright, so a wrong key can't overwrite a
  blob the right key opens. Without these an admin could make the server send a saved password to a server they
  chose, or in the clear (a security review reproduced it with a fake server). Don't relax it, and keep the client's
  `needsPasswordReentry`/`blankPasswordProblem` and the server rule in step. A blank Postgres password is built as a
  per-process filler, because `Password=` parses back as null and Npgsql then sends the host's `PGPASSWORD`. Hosts are
  an allowlist (names, IPs, SQL Server `host\instance`): `np:` pipes could start outbound SMB. Commands change only
  their own columns (`IDataSourceRepository.UpdateOnly`), because a whole-row write of an untracked read undid a
  concurrent turn-off. Turned-off is read from the row, fresh, before any connect (never from the cached catalog),
  and the cached catalog has no flag. The password is never returned by any endpoint
  (`ConnectionDto.hasPassword` only), never in audit details, and never in a log; connection strings come only from
  `SqlConnectionStringBuilder`/`NpgsqlConnectionStringBuilder`, never concatenation. A managed row's blob is AES-GCM
  with the row Id as associated data. The admin detail query must still open a source whose connection is broken
  (`catalogError`, `connectionUnreadable`), because that page is where it gets fixed.

## Conventions

- No comments explaining *what* code does; only *why*, for non-obvious constraints (see the
  Zustand/Radix/EF notes above for the tone/level of detail expected).
- Every new package-facing behavior gets documented in **both** `README.md` (root) and
  `src/QueryBuilder.Editor/README.md` (the NuGet-facing one) — check both when shipping a feature,
  and update the "Roadmap"/"What's included" lists to keep them accurate.

  existing `git log` style.
